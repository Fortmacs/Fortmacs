Elisp and Fortran, side by side

A real user option in both: grep-save-buffers, which says whether M-x grep saves changed buffers first, from Emacs's grep.el, and the same option in the form Fortmacs gives options whose value is a choice or a function of your own. Below each is what you would write in your init file.

Here Fortran takes fewer lines:

  • The declaration's type is the option's type. Elisp states it again for Customize in :type, five lines here; in Fortran the compiler checks every value against the declaration.
  • The choices are named constants, two lines for all three, so their names say what :tag strings say in Elisp.
  • One option holds either kind of value: = sets a choice, and => points it at a procedure of your own.

A real function in both: delete-space--internal, which deletes the spaces and tabs around point for M-\ (delete-horizontal-space), from Emacs's simple.el and from Fortmacs's port of it. Hover over any part (on a touch screen, tap it) of either version to see its counterpart in the other.

Fortran takes more lines, about twice as many, but the extra lines buy something:

  • Every variable is declared with its type and intent, so the compiler catches mistakes.
  • Each step runs in the order it is written. Lisp works from the inside out, so its reading order is not its running order: here delete-region is written first but runs last, after both positions are worked out. Many binding forms also work all at once by default, so one variable cannot use another: that is why Elisp has starred twins that bind one by one, let* beside let, if-let*, when-let*, and-let*, pcase-let*, cl-do* beside cl-do and cl-flet* beside cl-flet.
  • Every error is checked where it can happen.

Fortmacs is GNU Emacs rewritten in Fortran.
