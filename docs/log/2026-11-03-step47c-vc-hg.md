2026-11-03 — Step 47c: the Mercurial backend, vc-hg.el (`step47c-vc-hg`).  The new vc_hg_mod registers "Hg" with VC (after Git, in `init_bindings`; `vc_handled_backends` already lists it last, as upstream) and implements every backend slot vc_git_mod does: registered, state (`hg status -A` through `vc_hg_state_slow`), working revision, the mode-line string (`vc-hg--symbolic-revision` with the active bookmark and the `{shortest(node,6)}` template of `vc_hg_symbolic_revision_styles`), root and responsible-p, checkout model, create-repo, register, unregister, find-revision, the ignore file, checkout, revert (with `vc_hg_revert_switches`), delete-file(s), rename-file (renaming first, then `hg mv --after`), diff, previous revision, revision completion (branches, bookmarks, tags), checkin with `vc_hg_log_edit_mode` (C-c C-e toggles Amend through log-edit's `log_edit_toggle_amend`), print-log with `vc_hg_log_view_mode` (long format, short format from `vc_hg_root_log_format`, expanded entries indented by `indent_region`), and VC-Dir's dir-status-files (`hg status -mardu -C`, copies and renames), dir-printer and dir-extra-headers (`hg summary`).  `vc_hg_next_revision` is ported without a slot (no caller yet).  Hg has no show-log-entry, so vc_log_mod now falls back to vc.el's `vc-default-show-log-entry` (`log_view_goto_rev`).  `vc_state`, `vc_state_refresh`, `vc_backend`, `vc_registered` and its helper are now `recursive`: vc-hg-registered asks `vc_state` while `vc_state` asks `vc_backend`, as upstream.  Deferred: `vc-hg-state-fast` and the reading of .hg/dirstate, .hg/requires and .hgignore (Mercurial 5.7 and later create repositories with the `share-safe` requirement, which upstream does not understand, so upstream runs `hg status` as well), annotate, tags, branches, pull/push, working trees, patches, asynchronous checkins, Smerge resolution, and the rest listed in the vc_hg_mod row.  Tests: the new test_vc_hg_mod ports vc-hg-tests.el's vc-hg-after-dir-status and vc-hg-diff-revision-arguments (through `vc_hg_diff_flags`, the argument part of `vc_hg_diff`) and vc-tests.el's vc-test-hg00 to -hg06 and -hg10, with own tests of the version, mode line, previous/next revisions, C-x v l, C-x v L and C-x v d; the tests that run hg skip without it, as CI has only git.  Two owner questions (QUESTIONS-step47c-vc-hg.md): the init.f90 form of `vc_hg_symbolic_revision_styles` (a record array with kind constants used) and a `next_revision` slot (left out).
