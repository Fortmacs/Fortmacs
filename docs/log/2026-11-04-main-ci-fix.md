2026-11-04 — Fix main CI (`main-ci-fix`).  Main's CI failed on all five platforms after #258 (xref/etags) merged: the combined valgrind run (all suites in one process, only on main) reported 36 invalid reads in test_novice_mod `enable-and-disable-command` and exited with valgrind's error code 9.  Root cause: vc_hooks_mod's `vc_refresh_state` passed `buffers(current)%filename` straight to `vc_backend`; the Git backend's `temp_begin` makes a temporary buffer, and when that buffer grows the registry (`get_or_make_buffer` reallocates `buffers`), the old component is freed while the Hg backend still reads the dummy (`vc_find_root` → `locate_dominating_file` → `expand_file_name`).  Neither #257 nor #258 is wrong: together they create enough buffers in the earlier suites that the growth falls inside that call, which each one alone did not.  The PORTING.md hazard "a component of a registry passed as an argument to a procedure that changes that registry" applies; `vc_refresh_state` (`vc_backend`, `vc_file_clearprops`, `vc_mode_line`, `file_truename`), `vc_after_revert` and add_log_mod's `search_change_log_version_number` (`vc_working_revision`) now pass a local copy of the file name.  No test change.
