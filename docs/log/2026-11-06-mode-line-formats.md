2026-11-06 — Mode-line formats in Fortran (`mode-line-formats`).

Decision panel, question "how does a mode-line format, written in Fortran, name the computed parts that upstream writes as %-constructs?" (options: A named parts as segments, B a Fortran format and its parts as date_format_type, C procedures).  Claude's sealed pick, 2026-11-06T17:32:33Z, before reading either panelist: **A**.  A part is data in the segment list the header line already uses (typed segments, `%append`), it keeps upstream's field width exactly (a minimum, blanks on the right for strings, numbers right-justified) where B's `aW` pads on the left and truncates and so changes the text the mode line shows, which the owner kept unchanged; and unlike C, a plain identification needs no procedure, as Emacs needs no :eval for one.

The panelists' picks (each saw the options in its own order): Opus, named parts ("extends the decided typed segments; `aW` breaks the rule that the shown text is unchanged; a procedure for every padded name turns the exception into the rule"); Fable, named parts ("decision guide question 4: match what Fortmacs already uses; a plain `width=` component over a non-standard reading of an edit descriptor; the procedure stays the escape hatch").  All three agree: decided by the panel, posted on #272 with a Challenge box (#272's title now counts 54).

Applied: buffer_mod's `header_line_segment_type` has `part` (MODE_LINE_NONE, MODE_LINE_BUFFER_NAME for %b, MODE_LINE_BUFFER_PROCESS_STATUS for %s; the last is not MODE_LINE_PROCESS_STATUS, which Fortran's case-blind names would make display_engine_mod's hook `mode_line_process_status`: the role suffix names whose status it is) and a minimum `width`, and `%append` is a generic taking text or a part; display_engine_mod's `mode_line_part_text` (decode_mode_spec's %b and %s with display_mode_element's field width) replaces the two parsers of %-text (`expand_identification`'s %b, %Nb and %%, `expand_process_part`'s %s and %%) and serves the identification, a buffer's own `mode_line_format`, `mode_line_process` (its `mode_line_part_type` takes `part` and `width` too), the miscellaneous info and header and tab lines.  Converted: Info's identification (no more %% escaping of the manual and node names, nor of its `header_line` property), list-charset-chars' (`width=12`), Ediff's control buffer's, and comint's and compile's ":%s" (a colon, then the status part, in compile's face).
