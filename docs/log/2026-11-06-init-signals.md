2026-11-06 — The fatal signals of init_signals (`init-signals`).  sysdep.c:init_signals in part: system_dependent_mod's `initialize_signals`, which `execute_editor` calls before the editor starts (emacs.c:main), handles SIGHUP, SIGINT and SIGTERM even when they were ignored (maybe_fatal_sig: Fortmacs always runs interactively) and ignores SIGPIPE; the quit character's handler then replaces SIGINT's, as keyboard.c:init_keyboard does.  The handler, `deliver_fatal_signal`, only records the signal, as the SIGWINCH and SIGINT handlers already did; the polls end on it, keyboard_mod's wait for input then asks the command loop to exit (`request_exit`), and fortmacs_main's shutdown runs (`exit_fortmacs_hook`, the terminal reset, SIGHUP to the subprocesses), with the signal's number as the exit status, as emacs.c:terminate_due_to_signal calls kill-emacs with it.  `fortmacs_main`, which tests call, installs no handler, so a test runner keeps the default SIGTERM.  Shown end to end: the binary on a pty with SIGHUP ignored by its parent (`trap '' HUP`, the nohup case) exits with 15 on SIGTERM and 1 on SIGHUP; before, either signal killed it without the shutdown, and children inherited an ignored SIGHUP.
