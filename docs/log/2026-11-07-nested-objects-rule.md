2026-11-07 — Rules: nested objects, owner questions, "id" (`nested-objects-rule`, owner).  Three owner decisions, recorded in CLAUDE.md and PORTING.md so they stay rules.  Nested objects: what the configuration and the code reach is grouped by package, `main%sub%sub_sub` (`compilation%scroll_output`, `compilation%commands%compile`, `compilation%faces%error`, `mode_line%buffer_identification`), everything a package defines included (settings, per-buffer variables, hooks, keymaps, syntax tables, commands, faces); what has no package prefix upstream goes under `editor` (`editor%fill_column`, `editor%commands%find_file`); a further level only for a real sub-part (`mode_line%position%line_format`); M-x and help keep the flat names users type; packages are converted one pull request at a time, and the open #330, #331 and #332 are reworked to it before they merge (PORTING.md, "Nested objects").  Owner questions: when the owner asks about a name, a design or a convention, Claude answers and offers the choices, and decides, changes or pushes nothing for it without the owner's answer.  "id" is spelled out by meaning, identification (the face mode_line_buffer_identification, a mode line's identification) or identifier (a number identifying an entry), and faces are named in CLAUDE.md's no-abbreviations rule; the renames come in their own pull request.
