2026-11-05 — The first added feature, `fortran_completion_mode` (`fortran-completion-mode`), following the owner's decisions of 2026-11-05 (PORTING.md "Added features").  New modules: fortran_completion_mod (the buffer-local minor mode, off by default, with `fortran_completion_mode_hook` and `turn_on_fortran_completion_mode` for `f90_mode_hook`; its body adds `get_component_completion_data` to the buffer's `completion_at_point_functions`, so M-TAB, C-M-i, completion-preview and icomplete offer the candidates), fortran_declarations_mod (the parser: derived-type definitions with their components, bindings and parent types, and the variables declared with a derived type, each with the scope that declares it) and the generated fortran_completion_table_mod (the configuration API's types, written by the new tools/gen-completion-table.sh, which tools/build.sh runs after gen-faces.sh; listed in .gitignore).  After `%`, the designator before it is read back (names, subscripts and arguments in parentheses, blanks around `%`, continuation lines, any case); its first name is looked up in the buffer at point's scope, then among the module variables of the project's .f90 files, then in the configuration API, and each further name as a component of the type found so far (parent types included).  The buffer is parsed again when its text or accessible portion changes, a project file when its size or modification time does; the project's files are listed again once when a type is not found.  bindings_mod calls `init_fortran_completion` after `init_f90`; src/fortmacs.f90 exports the mode's command, its hook and `turn_on_fortran_completion_mode`.  The owner asked for the parsing on the worker thread: system_worker_mod's workers only read subprocess output (their messages are output and exit), so the parsing is synchronous behind the caches and "parsing on the worker thread" is Deferred (docs/status/fortran_completion_mod.md), with the typed name matched in any case, `associate` names, function results and fixed form.  Decided by rule: `get_component_completion_data` (verb first, R6-17; get_ for a lookup, "One word per meaning"), `turn_on_fortran_completion_mode` (the existing `turn_on_X` pattern for hooks), and the Fortran standard's own terms in the new names (derived type, component, binding, designator, declaration, scope).  tools/fortran-names.d keeps the generated table whole (its names are those of the checked sources); `quote` in the parser is `delimiter` (the standard's DELIM= wording).  Tests: test_fortran_completion_mod (own).
