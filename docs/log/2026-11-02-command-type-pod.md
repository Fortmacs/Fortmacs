2026-11-02 — `command_type` without allocatable components (`command-type-pod`).  The owner asked why commands_mod was still slow to compile after #192: a probe of the real 1,210-entry table compiles in 126 s at -O3 with the six allocatable components, 38 s with only `name` allocatable, 1 s with none.  So: `disabled_message`, `advertised_binding`, `repeat_hint` and `info_file` are fixed-length strings ("" for none; the lengths are `DISABLED_MESSAGE_MAX` 400, `ADVERTISED_BINDING_MAX` 32, `REPEAT_HINT_MAX` 80, `INFO_FILE_MAX` 64), `repeat_continue` a fixed array of `REPEAT_CONTINUE_MAX` (8) handles filled with `append_repeat_continue` (the null handle ends it), and `name` a fixed-length string of `COMMAND_NAME_MAX` (64; the longest built-in name has 43) read with `trim` where it is concatenated.  tools/hazards.awk's `command-component` rule now reports any allocatable component of `command_type`; the Hazards section and checklist say so.  The sites that changed were found by renaming the component and letting gfortran list every use.
